## Common Pitfalls / Stop Conditions

- **Baseline laundering (BLOCKER):** no snapshot changes before a written DOM/geometry disposition.
- **Sleep-based masking (HIGH):** replacing 500ms with a larger arbitrary timeout is not a fix; wait on a stable semantic owner and still preserve screenshot assertions.
- **Fixture broadening (HIGH):** do not return richer catch-all responses simply to make screenshots resemble history; new endpoint stubs must match production response shapes and route ownership.
- **Shared-shell overreach (HIGH):** a multi-route diff does not by itself prove `MainLayout` is wrong; shell geometry must fail independently.
- **Admin/Purchasing promotion (BLOCKER):** Admin Data may receive only demonstrated regression fixes or evidence-approved snapshots; Purchasing likewise. No Data Workspace adoption is authorized.
- **Artifact destruction (HIGH):** every Playwright run may clear transient `test-results`; the controlled source run must target a unique evidence-owned output root and atomically seal all 105 members before another invocation.
- **Orchestration false-positive (CRITICAL):** prose, logs, or regex matches cannot advance plans. Every plan emits a typed result JSON; downstream execution requires COMPLETE plus committed SUMMARY/dependency commits and matching hashes.
- **Windows argv truncation / shell interpretation (CRITICAL):** never concatenate executable and arguments. Use Node `child_process.spawn` or `execFile` with `shell: false`, explicit argv and explicit cwd. Probe exact round trips for spaces, Unicode, quotes and metacharacters before source authorization.
- **Classifier identity inference (BLOCKER):** never parse title text or search for viewport substrings. Canonical test identity is exact `{project,normalizedSpecPath,canonicalTitle}` from list-only preflight; expected failure identity additionally requires the frozen snapshot name from structured result/attachments. Viewport metadata comes only from project/result attachment metadata. Attempt v2 remains `REJECTED_CLASSIFIER`; its otherwise exact 76/21 outcome cannot be retroactively accepted.
- **Discovery escape (BLOCKER):** one canonical direct-Playwright argv base must name both `tests/visual-routes.spec.ts` and `tests/pagination-visual.spec.ts`, exact recovery config, Chromium project and one worker. List-only preflight and source must produce the same complete canonically sorted/hashed `{project,normalizedSpecPath,canonicalTitle}` set across passing/failing tests. Missing, extra, duplicate, omitted pagination, added spec, config/project drift or set mismatch blocks acceptance.
- **Indirect shell/server launch (BLOCKER):** npm/npx/package scripts, command strings and shell intermediaries are forbidden for source/preflight. Playwright internal `webServer.command` is bypassed by a dedicated no-webServer recovery config; Vite and Playwright are resolved JS CLIs launched through `process.execPath`, `shell:false`, explicit argv/cwd/env, with executable hashes and argv frozen.
- **Attempt identity laundering (BLOCKER):** the consumed malformed-path invocation remains `REJECTED_SETUP` under its original ID. Its zero identities cannot satisfy inventory. A new cryptographic ID is authorized only after preflight; exactly-once is per accepted ID and only one source attempt may become `ACCEPTED`.
