# Phase 27.1 — Validation Strategy

## Validation contract

A screenshot mismatch is never self-explanatory. Every one of the exact 21 source failures must retain expected/actual/diff plus route/state/viewport identity, repeated semantic DOM and geometry, fixture/request completion, browser errors and a lowest-owner disposition. No production or baseline edit may precede that row's disposition. Baseline acceptance is selective and requires semantics, DOM, geometry and intent evidence; screenshot appearance alone is insufficient.

Admin Data implementation and Purchasing adoption remain locked. The only permitted changes in those domains are a demonstrated smallest-owner regression correction or individually proven stale snapshot replacement. Threshold `maxDiffPixelRatio: 0.02`, viewport matrices, screenshot assertions, route fixtures and comparison logic remain unchanged unless a separately evidenced harness defect is replaced by a stricter deterministic assertion.

- Every plan closes through a non-circular two-artifact terminal protocol. The marker never contains or claims its own commit hash.
- At each serialized boundary (`01 → 02 → 03 → 04 → 05 → 06 → 07`), the validator proves current HEAD is a terminal-marker commit containing exactly the frozen marker path and no other path; the marker is COMPLETE; its referenced payload commit is reachable and contains matching payload-result/SUMMARY hashes; and every exact dependency terminal marker appears once with matching path/hash/commit and independently validated COMPLETE status. Reject result-before-SUMMARY, marker-before-payload, unknown/missing fields, extra marker-commit paths, unreachable payload, hash mismatch, duplicate/wrong dependency and non-COMPLETE dependency. HALTED/FAILED never advance; free-text advancement is prohibited.
- Plan 01 freezes `phaseBaseCommit`, all seven payload-result paths, all seven terminal-marker paths, and every pre-phase index/worktree/untracked path/hash. Plan 01 uses `phaseBaseCommit`; each later wave uses the validated predecessor terminal-marker commit as `waveBaseCommit`. Cumulative accounting retains all payload/marker commits in `phaseBaseCommit..HEAD` plus current state. Independently, wave-local accounting uses `terminalMarkerCommit..HEAD` plus current index/worktree/untracked, thereby excluding every predecessor artifact while retaining same-wave commits. Fixtures prove result after SUMMARY, marker after payload, predecessor exclusion wave-locally, cumulative payload/marker retention, authorized same-wave committed paths, wrong base, unrelated pre-existing dirt and extra tracked/untracked paths.
- Plan 01 preauthorizes only exact fixed final-gate members: `evidence/final-gate/run-1` and `run-2` closed manifest/output slots plus fixed `unit-rung-manifest.json`, `lint-rung-manifest.json`, `depcruise-rung-manifest.json`, `build-rung-manifest.json`, and `hygiene-rung-manifest.json`. Fresh run IDs exist only in manifest content. Extra files, path substitution, duplicate slots, and unlisted rung outputs fail.
- Closeout uses tested `runPhase271FinalGate.ts` with structured launcher configuration only (never a visual command string). Before each complete pass it re-lists the exact frozen two-spec set and requires discovery SHA-256 equality. The shared launcher directly owns the Vite no-webServer lifecycle for both passes: both complete serial/one-worker visual runs write and fsync durable outputs in one unique OS temp directory outside the repository. Immutable execution-input Git hashes before/between/after must match byte-for-byte. Only after both runs and ordered rungs attest are exact fixed members imported atomically; full Git delta must equal only those members, imported hashes are verified, then temp is deleted.
- Stop on any `FAIL`, `GAP`, `NEEDS_EVIDENCE`, `UNRESOLVED`, nondeterministic repeated packet, unexplained changed file/hash, oracle weakening, or scope promotion.

## Evidence packet schema

The attempt ledger is append-only and closed-schema: the consumed path attempt keeps its original ID and terminal `REJECTED_SETUP`; attempt v2 keeps its original attempt/session/run evidence and terminal `REJECTED_CLASSIFIER`, discovery hash `855caa1ec12583b2baaae7db7aedfabe45e735702f12b135168d7f504cdd39d1`, 76 discovered tests and 21 screenshot failures. Neither can transition to accepted. Attempt v3 receives a cryptographically new ID only after pure classifier fixture/hash, argv, discovery preflight and path gates pass. Exactly-once is evaluated per authorized attempt ID and no more than one source attempt can have terminal `ACCEPTED`. The rejected setup entry's zero collected identities are never treated as an empty successful inventory.

The controlled source run writes into a unique evidence-owned root outside transient output, or an ASCII-safe unique OS temp staging root when required. Playwright is invoked directly as `process.execPath` plus resolved-and-hashed CLI JS and canonical two-spec/config/project/worker argv; Vite is likewise invoked directly via its resolved-and-hashed CLI JS. Both use `spawn`/`execFile`, `shell:false`, explicit argv/cwd/env. npm/npx/package scripts, command strings, shell intermediaries and Playwright internal webServer commands are forbidden. The dedicated recovery config disables webServer and must remain production-equivalent. Preflight adds only list+JSON flags; source adds only JSON reporter/result output and run output directory. Both must yield an identical complete, duplicate-free, canonically sorted and hashed set of `{project,normalizedSpecPath,canonicalTitle}` across all tests, including pagination. Package-script token equivalence is a separate drift gate. Probe children cover spaces, Unicode, quotes and metacharacters for both CLIs. Preflight is not source execution. External staging is closed, hashed and fsynced before atomic same-volume import to phase evidence; imported hashes are rechecked before acceptance and cleanup. Canonical identity never uses parsed title or viewport substrings: it is exact project + normalized spec path + canonical list-only title; expected-failure matching also requires exact frozen snapshot name, and viewport is read from project/result attachment metadata. The sanitized attempt-v2 fixture and golden 21 identity manifest are frozen test inputs with a canonical manifest SHA-256. Its structured result must contain exactly the frozen 21 failure identities and no Warehouse, timeout, navigation, setup, arbitrary assertion or other nonvisual failure. Fewer, more, different and duplicate identities fail. Preservation stages and hash-checks all members, then atomically renames the complete tree; cleanup, partial-copy and interrupted-process tests must prove no accepted partial manifest can exist.

Before any later Playwright invocation, `packet-member-manifest.json` must expand exactly 105 concrete destinations: `evidence/packets/row-01` through `row-21`, each containing exactly `expected.png`, `actual.png`, `diff.png`, `error-context.md`, and `trace.zip`. Every destination records absent-at-freeze/current SHA-256 and belongs to the frozen infrastructure allowlist; extra or missing member tests must fail.

The independently hashed `row-class-path-matrix.json` freezes all 21 rows against four classes. Production paths are the research-named row owner only; fixture paths are the named route fixture (Phase-09 uses `phase9-test-fixture.ts`); harness paths are only the named visual spec/collector seams; stale paths are only the row's exact snapshot. Validators reject cross-row/class laundering, production paths for fixture/harness classes, and snapshots for non-stale classes.

Each row must contain:

- stable failure ID and source row number;
- family, route URL/query, actor/fixture/state, viewport and snapshot path;
- source commit, Playwright/config/fixture hashes and exact command;
- expected/actual/diff/error-context/trace paths, SHA-256 and PNG dimensions;
- H1, landmarks, selected tabs, named primary owner and boxes;
- document/client dimensions, horizontal overflow and local overflow owners;
- visible copy inventory relevant to the mismatch;
- fixture requests with status/completion; console/page/request errors;
- two pre-edit actual/DOM/geometry hashes;
- final disposition (`production-regression`, `stale-baseline`, `fixture-drift`, `harness-nondeterminism`), lowest owner, rationale and authorization;
- changed path plus before/after SHA-256 when an edit is authorized;
- final `RESOLVED` only after focused rerun passes.
