## 1. Intent and Evidence

Following completion of the MRX Round 3 Closure (`D1–D8`), an expert-backed `/ponytail-audit` of the MRX Frontend architecture across all 7 MRX routes (`/`, `/weekly-menu`, `/warehouse`, `/chef`, `/reconciliation`, `/admin-data`, `/settings/advanced`) evaluated URL-as-Single-Source-of-Truth (`searchParams`), dual-tier SWR cache coherence (`serverStateCache` L1 memory + L2 `sessionStorage`), keyed remount lifecycles, and `DOM-MODE-1` component-level boundaries. It surfaced 9 actionable findings (`E1–E9`):

## 2. Technical Design

### 2.1 E1, E2, E6, E9 — SWR Cache Coherence, Snapshot Key Standardization, Catalog Dish Caching, and Modal Read Caching

1. **`mrxCacheInvalidation.ts` & `useReconciliationWorkspace.ts` (`E1`):**
   - Rename `RECON_SNAPSHOT_KEY` in `useReconciliationWorkspace.ts` (`line 33`) from `'snapshot:reconciliation'` to `'snapshot:mrx_reconciliation'`, and also include `serverStateCache.invalidatePrefix('snapshot:reconciliation');` inside `invalidateMrxCaches()` (`frontend/src/api/mrxCacheInvalidation.ts`) so any pre-existing L2 `sessionStorage` entry from an older tab/session is evicted too.
   - In `useReconciliationWorkspace.ts`:
     - At `initialReconCache` (`lines 81-83`), prefer `serverStateCache.get<ReconciliationBatchSummary>(reconCacheKey)?.data` first, falling back to `snapshot?.batchId === batchId && snapshot.serviceDate === serviceDate ? snapshot.data : null`.
     - In `handleComplete` (`lines 290-309`), also write `serverStateCache.set(RECON_SNAPSHOT_KEY, { batchId: completed.batchId, serviceDate, data: summary }, { persist: true });` so the persisted snapshot matches the completed batch.
2. **`useWorkbenchQuery.ts` & `MrxCookingWorkbench.tsx` (`E2`):**
   - In `useWorkbenchQuery.ts` (`lines 198-206`), when `entryOnMount && !entryOnMount.isStale`:
     - Extract `const payload = entryOnMount.data as T;`
     - Call `setDataState(payload);` and `setResolvedCacheKey(cacheKey);` before `return;` so `stateData` and `resolvedCacheKey` are permanently synchronized with the warm cache hit, preventing any revert when the 60s TTL later expires.
   - In `MrxCookingWorkbench.tsx` (`line 44`), scope `snapshotKey` by `batchId`: `snapshotKey: batchId ? \`snapshot:mrx_cooking_\${batchId}\` : undefined`.
3. **`useMrxSourceEdit.ts` (`E6`):**
   - Cache the aggregated active dish catalog in `serverStateCache` under `'mrx_catalog_dishes'` (`const DISH_CATALOG_CACHE_KEY = 'mrx_catalog_dishes'`).
   - In `load()`, check `const cachedDishes = serverStateCache.get<DishOption[]>(DISH_CATALOG_CACHE_KEY);`. If `cachedDishes && !cachedDishes.isStale`, reuse `cachedDishes.data` without calling `adminApi.getDishes`; otherwise fetch all pages, sort, and store via `serverStateCache.set(DISH_CATALOG_CACHE_KEY, mappedDishes)`.
4. **`MrxBatchDishesModal.tsx` & `ReconciliationIssueDetailModal.tsx` (`E9`):**
   - In `MrxBatchDishesDialog` (`MrxBatchDishesModal.tsx`), check `const cacheKey = \`mrx_batch_dishes_\${batchId}\`; const cached = attempt === 0 ? serverStateCache.get<MrxBatchDishSummary[]>(cacheKey) : null;`. If `cached && !cached.isStale`, initialize `dishes` from `cached.data`, `selectedDishId` from `cached.data[0]?.dishId ?? null`, `isLoading = false`, and skip the network fetch in `useEffect`; on network fetch success, call `serverStateCache.set(cacheKey, items || [])`.
   - In `ReconciliationIssueDetailDialog` (`ReconciliationIssueDetailModal.tsx`), check `const cacheKey = \`mrx_issue_detail_\${issueId}\`; const cached = attempt === 0 ? serverStateCache.get<MrxInventoryIssueDetail>(cacheKey) : null;`. If `cached && !cached.isStale`, initialize `issue` from `cached.data`, `isLoading = false`, and skip the network fetch in `useEffect`; on network fetch success, call `serverStateCache.set(cacheKey, data)`.

### 2.2 E3, E4, E5, E7, E8 — URL-as-SSOT Synchronization, Smooth Unkeyed Scope Switching, and Component-Level `DOM-MODE-1` Guards

1. **`useReconciliationWorkspace.ts` & `ReconciliationCompletedBranch.tsx` (`E3`, `E8`):**
   - **URL `?customerId=` synchronization (`E3`):**
     - Add a `useEffect` watching `[urlCustomerParam, customers]`: when `urlCustomerParam` is non-empty and `customers.length > 0`, find `matched = customers.find(c => c.customerCode === urlCustomerParam || c.customerId === urlCustomerParam)`. If `matched && matched.customerCode !== customerCode`, update `setCustomerCode(matched.customerCode)`, `setHasBatchesLoaded(false)`, and `setIsLoading(true)`.
     - In `handleSelectCustomer(code)` (`lines 327-347`), update `searchParams` so `if (selectedCustomer?.customerId) nextParams.set('customerId', selectedCustomer.customerId); else nextParams.delete('customerId');`, delete `batchId`, and delete `lineStatus`.
   - **Resetting stale `lineStatus` filter across batch transitions (`E8`):**
     - In `handleSelectBatch(nextBatchId)` (`lines 349-367`), call `setLineStatusFilterState('ALL')` and `nextParams.delete('lineStatus')`.
     - In `ReconciliationCompletedBranch.tsx` (`line 88`), navigate cleanly to `/reconciliation?view=lines&batchId=${row.batchId}&date=${row.weekStartDate}` (which omits `lineStatus`, and in `useReconciliationWorkspace.ts` sync `lineStatusFilter` when `searchParams.get('lineStatus')` changes or is removed so `setLineStatusFilterState((searchParams.get('lineStatus') as LineStatusFilter) || 'ALL')` stays in lockstep with URL navigation).
2. **`WeeklyMenuPage.tsx` & `useMrxBatchWorkspace.ts` (`E4`):**
   - In `WeeklyMenuPage.tsx` (`lines 60-62`), remove `key={`${searchParams.get('customerId') ?? ''}:${searchParams.get('weekStartDate') ?? ''}`}` from `<MrxBatchWorkbench />` so `MrxBatchWorkbench` remains mounted across URL parameter updates.
   - In `useMrxBatchWorkspace.ts` (`lines 181-189`), ensure the URL sync `useEffect` updates `customerId` and `weekStartDate` cleanly when `searchParams` changes without clearing `changeMessage` when triggered by `handleImportSuccess`.
3. **`MrxCookingWorkbench.tsx` (`E5`):**
   - Synchronize `fallbackBatchId` whenever `urlBatchId` is present (`useEffect(() => { if (urlBatchId && urlBatchId !== fallbackBatchId) setBatchId(urlBatchId); }, [urlBatchId, fallbackBatchId])`).
   - When `!urlBatchId && fallbackBatchId`, update `searchParams` (`replace: true`) with `batchId = fallbackBatchId` so clicking the sidebar link `/chef?view=mrx-cooking` keeps the displayed batch (`fallbackBatchId`) and URL `?batchId=` in 1:1 agreement.
4. **`WarehousePage.tsx` & `ChefDashboardPage.tsx` (`E7`):**
   - In `WarehousePage.tsx`, define `const mrxView = viewParam === 'mrx-daily' || viewParam === 'mrx-preparation' || viewParam === 'mrx-delta';` and guard `if (mrxView && operationalMode !== 'MATERIAL_RECONCILIATION') return <Navigate to="/forbidden" replace />;` before branching on `viewParam`. Ensure existing unit tests in `Warehouse.test.tsx` and `Chef.test.tsx` (which check `operationalMode` via `useWorkspaceSessionStore`) remain 100% compatible (in tests where `operationalMode` defaults to `'MATERIAL_RECONCILIATION'` or is explicitly set).
   - In `ChefDashboardPage.tsx`, define `const mrxView = viewParam === 'mrx-cooking';` and guard `if (mrxView && operationalMode !== 'MATERIAL_RECONCILIATION') return <Navigate to="/forbidden" replace />;` before `if (viewParam === 'mrx-cooking')`.

## 3. Acceptance Criteria Matrix (`AC-E1` to `AC-E9`)

- **AC-E1:** `invalidateMrxCaches()` clears `'snapshot:mrx_reconciliation'` (and legacy `'snapshot:reconciliation'`), `handleComplete` updates the reconciliation snapshot, and returning to `/reconciliation` after an MRX mutation never hydrates stale pre-mutation lines from snapshot storage.
- **AC-E2:** Switching `useWorkbenchQuery` `cacheKey` (`A -> B -> A`) onto a warm cache entry updates `stateData` and `resolvedCacheKey` immediately so expiring the 60s TTL on `A` never reverts `data` to `B`; `MrxCookingWorkbench` scopes its snapshot key per `batchId`.
- **AC-E3:** On `/reconciliation`, changing `?customerId=` via same-mounted URL navigation updates the active customer, and selecting a customer via `handleSelectCustomer` updates `customerId` in `searchParams`.
- **AC-E4:** `<MrxBatchWorkbench />` in `WeeklyMenuPage.tsx` transitions across customer/week selection and Excel menu import without unmounting/remounting, preserving `changeMessage` and avoiding duplicate `getCustomers()` / `getSourceChangeInbox()` / `getDishes()` calls.
- **AC-E5:** On `/chef?view=mrx-cooking`, navigating from `?batchId=batch-2` to `/chef?view=mrx-cooking` (no `batchId` param) preserves `batch-2` and synchronizes `?batchId=batch-2` in the URL instead of snapping back to stale `batch-1`.
- **AC-E6:** `useMrxSourceEdit` caches `adminApi.getDishes` in `serverStateCache` (`'mrx_catalog_dishes'`), eliminating repeated multi-page dish catalog fetches across week/customer/version changes.
- **AC-E7:** `WarehousePage` and `ChefDashboardPage` redirect `?view=mrx-*` to `/forbidden` if `operationalMode !== 'MATERIAL_RECONCILIATION'`, matching `WeeklyMenuPage`.
- **AC-E8:** Switching batches in `/reconciliation` or navigating from `ReconciliationCompletedBranch` (`?view=completed` -> `?view=lines`) resets `lineStatusFilter` to `'ALL'` so completed/target batches never render blank due to a leftover filter.
- **AC-E9:** `MrxBatchDishesModal` and `ReconciliationIssueDetailModal` reuse warm `serverStateCache` entries (`mrx_batch_dishes_${batchId}`, `mrx_issue_detail_${issueId}`) when reopened for the same ID, and clear automatically on `invalidateMrxCaches()`.
