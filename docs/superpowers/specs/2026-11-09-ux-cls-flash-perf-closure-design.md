## 3. Technical Design

### 3.1 `F1` — Zero Header Wrap & Smooth `keepPreviousData` on `/reconciliation` Customer/Week Switches (`CLS: 0.43440 -> 0.00000`)

1. **[`PaginationBar.tsx`](file:///d:/ki7/PRN222%20Doanh%20Nghiệp/IPCManagement/frontend/src/components/workbench/PaginationBar.tsx#L21-L28):**
   - For `placement === 'selector'` (`isSelector === true`), change `showNavigation` so it only renders visible controls when multi-page navigation is actually known to exist:
     ```ts
     const showNavigation = isSelector
       ? (totalPages !== undefined && totalPages > 1) || page > 1 || hasPrev || hasNext
       : totalPages === undefined || totalPages > 1 || page > 1 || hasPrev || hasNext;
     ```
   - This prevents `PaginationBar` (`placement="selector"`) from popping out of `sr-only` into a `Trang 1/—` + 2-button widget during the `18ms` window while `catalogInfo` is `undefined`, eliminating the `56px -> 99px -> 56px` `<header>` wrap on `/reconciliation`, `/warehouse?view=mrx-daily`, and `/chef?view=mrx-cooking`.
2. **[`useReconciliationWorkspace.ts`](file:///d:/ki7/PRN222%20Doanh%20Nghiệp/IPCManagement/frontend/src/features/reconciliation/hooks/useReconciliationWorkspace.ts#L88-L96) & `handleSelectCustomer` / `handleSelectDate` (`lines 349-424`):**
   - Retain `storedData` as the visible `data` while transitioning to a new customer or cross-week date (`const data = storedData;`) and compute:
     ```ts
     const isScopeTransitioning = !batchId ? (!hasBatchesLoaded || isLoading) : (loadedScope !== reconCacheKey || storedData?.batchId !== batchId);
     const isPreviousData = Boolean(data && isScopeTransitioning);
     ```
   - When `hasBatchesLoaded` finishes and the new customer or week legitimately has zero batches (`!batchId && hasBatchesLoaded && !isLoading`), `data` resolves to `null` so the empty state (`"Chưa có lô đối soát cho khách hàng này"`) renders cleanly without getting stuck on the old customer's table.
   - In `handleSelectCustomer` (`line 349`) and cross-week `handleSelectDate` (`line 395`), if warm cached batches (`mrx_batches_${customerId}`) and warm cached summary (`mrx_recon_${firstBatchId}_${firstWeek}`) exist in `serverStateCache`, hydrate `batches`, `batchId`, `serviceDate`, `data`, and `loadedScope` synchronously during the event handler so switching back to a previously visited customer (`Recon_02_Switch_Customer_Back`) is a **0ms synchronous render** with zero network waterfall and zero loading state.

### 3.4 `F4` — In-Flight GET Request Deduplication & Elimination of StrictMode `499` Self-Aborts and Redundant Catalog Fetches

1. **In-Flight GET Deduplication in [`client.ts`](file:///d:/ki7/PRN222%20Doanh%20Nghiệp/IPCManagement/frontend/src/api/client.ts#L139-L154):**
   - Maintain a module-level `inFlightGetRequests = new Map<string, Promise<unknown>>()` in `client.ts`.
   - When `apiClient<T>(endpoint, options)` is called with `method === 'GET'` (or default `undefined`) and `!options.signal`:
     - Key by `${token ?? 'anon'}:${url}`.
     - If an in-flight promise exists for that key, return it directly instead of opening a duplicate `fetch()`.
     - Delete the key in `.finally()`.
