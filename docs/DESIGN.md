# Design — canonical presentation contract

Read only the relevant section, then actual source/primitives and rendered tests. [DOMAIN](DOMAIN.md) owns language/status/grain; bounded contracts own feature permissions/readiness. [ENGINEERING](ENGINEERING.md) owns browser/performance verification. This owner defines presentation grammar and stable rule IDs, not task state, specimen history or runtime certification.

## Authority and approval boundaries

MUST is an invariant, SHOULD a strong default with an evidenced bounded justification, MAY an option. Data safety → accessibility → layout stability → performance → visual consistency → aesthetics. Generic examples cannot invent data/actions, override a bounded contract, or authorize changes to every route. Fix the lowest root owner; no parallel BadgeV2/TableNew/ModalCustom owners.

**OWNER_DECISION_REQUIRED — density (T8):** no product choice between three persisted densities/reset REQUIRED and density preference OPTIONAL/PROVISIONAL is established. Existing capability/defaults do not select policy. Do not use T8 as a blanket acceptance gate or silently permit new exceptions.

Additional approval boundaries retained without choosing new policy:
- Minimum 12px data text is the existing safety-conservative floor; its classification as unconditional invariant versus provisional reconstruction target still requires owner confirmation. Do not lower it while unresolved.
- D6's typography maximum-six applies to size levels, not a count of semantic text roles; more role labels do not justify more levels. Zero-radius table surfaces plus three nonzero radius tiers describe different scopes, not four rounded tiers.
- D7's one-primary default and a destructive decision partner do not authorize two same-primary actions. Whether a particular decision pair qualifies is a bounded product/design decision; do not infer it from a specimen.
- T7 is mandatory for horizontally scrolling tables; sticky/frozen advice elsewhere describes tables without that condition, not a weaker alternative.
- M1.2's one blocking layer and retained nested-confirmation mechanics in the planning contract have unresolved product applicability. Preserve existing behavior; any change to the overlapping case needs an explicit owner decision, not this documentation synthesis.

## Foundations and visual grammar

Quiet Operational: flat cool-slate surfaces, hairline boundaries, precise food-service logistics rather than landing-page decoration. Semantic role tokens distinguish primary-action navy from informational blue and critical warning/danger. Routine states stay quiet; MRX contextual tones come from DOMAIN. Do not clone external Fiori/Carbon/ISA visual branding or copy a specimen as production authority.

Use current source tokens, not a second literal token dictionary. Candidate reconstruction values remain candidates: body/table 13–14px, headers/metadata >=12px, heading hierarchy 18/16/14px; 4px base spacing (4/8/12/16/24/32px); square tables, small input corners, bounded button/dialog corners. No pill-rounded table status/buttons, heavy row/card shadows, long all-caps or line-height 1.0 that clips Vietnamese accents. Natural multiline growth wins over fixed row clipping. Density/control heights are candidate geometry, not a chosen density policy.

Local Inter Variable font, system fallback and metric/preload strategy must honor CSP font-src self. Measure Vietnamese glyphs, native zoom and font-swap CLS; old specimen metrics are not proof. Dynamic/numeric text uses tabular figures. Icons share Lucide-compatible monochrome stroke 2/viewBox24; standard 16px controls and 18–20px navigation, icon boxes shrink-safe and optically centered. Distinct business metaphors must not overload one glyph for unrelated meanings. Flaticon is research-only: never import its SVG/PNG as production assets; new domain glyphs use normalized vector grammar.

## Composition and navigation

A route has one primary work object; ordered regions are identity/context → scope/commands → lifecycle/readiness → state/work surface → detail/footer when present. Each region needs one owner, not mandatory decorative boxes. Choose dashboard/action queue, worklist, matrix, dense workspace, master/detail, object document, decision, editor, locked record or report by the actual task. Lists default to 5–7 decision fields and detail disclosure; inherently two-dimensional matrix/report contracts need their own declared grain, not forced arbitrary column loss.

Scope for shareable navigation should restore from canonical URL; server-authoritative scope must remain server-owned. Local drafts are not durable state. Personal preferences may use client storage only as presentation memory; customer/week/batch localStorage never becomes competing business authority. No duplicate sidebar workspace set plus identical page tabs. Actual MainLayout/route/permission owners define production navigation; sidebar targets or specimen rails do not authorize cutover.

Disclosure uses button type=button + aria-expanded; actual destinations are separate anchors with aria-current. aria-controls is guidance when useful, not blanket required ID plumbing. Deep links reveal active ancestors; SHOULD promote a single allowed child with an unambiguous label, but specimen acceptance never makes promotion mandatory. Compact rail is OPTIONAL/PROVISIONAL; expanded-to-temporary-drawer is a recommendation. Wide/medium/narrow layouts preserve real reading order, scope/content adjacency and useful actions, not only zero overflow. Tabs/grids use appropriate roving arrow/Home/End behavior; website disclosure navigation uses Tab/Shift+Tab/Enter/Space (arrows optional).

P9 readiness: before changing UI, identify purpose/work object, actor/visibility/actions, source/grain/mode, preconditions/postconditions, next owner, failure/recovery, route/scope/state composition, approved reference and acceptance. Link unchanged facts rather than making another plan/report owner. Preview in the same frontend app reuses auth/API/domain primitives. SANDBOX_ONLY is not production acceptance or a permanent second implementation; PRODUCTION_OWNER_REUSE mounts the real presentation with a thin adapter. No mutation/cutover without specific authority; atomic promotion retires the sandbox. Extraction/wrapping legacy primary surfaces is not full presentation replacement. Preserve behavior, financial arithmetic and permission truth; never delete tests to certify a design.

## Interaction, query and motion

Default/hover/pressed/focus, disabled/unavailable, pending, invalid, selected/indeterminate, current route, expanded, readonly/locked, stale, active ancestor and drag/reorder are distinct states. Native disabled removes activation/tab; aria-disabled remains focusable with activation guards and explanatory reason (no pointer-events none); readonly preserves copying/focus/contrast; locked records explain provenance. Pending prevents duplicate writes while preserving required focus/geometry; opt-in focus-preserving pagination is not a generic native-disabled rule. Error styling must not erase visible focus; current-route marker survives focus; selected hover and disabled checked state remain recognizable.

Uninitialized/loading/refresh/ready/empty/denial/error/prerequisite/partial/conflict/stale/read-only have different surfaces. No invented zero/empty before authoritative data. Same-key permitted retention may remain read-only during refresh, but active-key/mode/denial/readiness rules from bounded owners always win. Generic stale-while-revalidate never leaks previous-key data or turns 403 into cached content. Exactly one explanatory surface per work-object/grain/state; summary/detail repetition needs a different actor/grain and additional nonduplicate facts.

Motion must not encode required information alone, must respect prefers-reduced-motion, and leave state/focus understandable without animation. Transform/opacity are safest defaults; nonessential accessible small-surface focus/color/shadow transitions are allowed. Avoid layout-affecting animation without justification and measured scope. Grid-row disclosure is OPTIONAL_IMPLEMENTATION_PATTERN, not REQUIRED or performance certification. Semantic motion defaults 0/100/150/200ms and standard/enter/exit easing are recipes, not universally validated production mechanics. Reduce positional movement/skeleton pulsing and animated scrolling; static activity remains understandable.

## Acceptance and maintenance

**Q0:** technical rule gaps may be clarified only with evidence/scope/valid exceptions/oracle and credible regression; this never changes business/permissions/mode/design direction or unapproved thresholds. Existing rule → fix owner/enforcement, not duplicate rule IDs or weaker expectations. **Q1:** review applicable rules, computed actual primitive variants/hit targets and all overlay exits; no fake class or disabled primary. Product identity zone excludes internal preview/build/debug labels unless approved business/audit fact. **Q2:** distinguish selected performance/accessibility targets from measured evidence; **Q3:** implement only authorized findings at root owners, not an implicit whole-product campaign.

Rendered acceptance records work-object/state/actor/viewport, explanatory-surface count, heading/scope/state/content boxes/order, semantic geometry/min-height, useful occupied space and next-action focus. No oracle means NEEDS_EVIDENCE even with no overflow. Verify field/control/composition, modal/portal cleanup and natural async transitions; preserve query/version/permission guards. Headed screenshots are candidate references, never persistence/performance/whole-product proof. Standards references: WCAG 2.2/ARIA APG, NN/g, web.dev, Carbon/Atlassian/Fiori, ISA-101 and MDN inform these rules but are not a second project authority.
